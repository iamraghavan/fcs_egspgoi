# Backend Requests from the UI/UX Redesign

The redesign is **UI-only** (no API, schema, auth or business-logic changes). These requested features
cannot be delivered properly without backend support. Each item says what the UI needs, why, and what
the UI will do in the meantime. Priority: **P1** = blocks a core flow in the brief, **P2** = important,
**P3** = nice to have.

| #     | Feature (brief section)                                                                  | What the backend would need                                                                                                          | Interim UI behaviour                                                                                                 | Priority   |
| ----- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- | ---------- |
| BR-1  | **Draft claims + autosave** (New Claim flow)                                             | `draft` status for positive credits, save/update draft endpoint, drafts excluded from totals and review queue                        | Autosave to the **browser only** (localStorage), with "Saved on this device" wording                                 | P1         |
| BR-2  | **"Returned for changes"** (Reviewer queue, My Claims)                                   | New status + reviewer comment field + faculty resubmit endpoint; history entries                                                     | Reviewer can only **Approve / Reject** (with a required comment shown in UI; stored only if the API accepts `notes`) | P1         |
| BR-3  | **Credit target per faculty** ("earned / target" ring)                                   | Target per designation/department/academic year, endpoint returning target with the summary                                          | Show balance + trend; no ring percentage                                                                             | P1         |
| BR-4  | **Reviewer roles (HOD / IQAC / Dean)** with department-scoped queues                     | New roles + permissions, department scoping on list endpoints, multi-step approval (the policy engine already models `approvalPath`) | Queue is admin-only, all departments                                                                                 | P2         |
| BR-5  | **Academic year as a managed entity** (switcher, settings tab, archiving)                | Academic-year list endpoint (current, open/closed), validation on credits                                                            | Switcher built from years found in the data (client side)                                                            | P2         |
