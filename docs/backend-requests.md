# Backend Requests from the UI/UX Redesign

The redesign is **UI-only**: no API, schema, auth or business-logic changes. The UI is designed only for
what the current API supports, with no non-functional prototypes. Everything below needs backend work
first. Until then the UI shows the "Interim UI" behaviour, which uses existing endpoints only.

Priority: **P1** = blocks a core flow or is a known defect; **P2** = important; **P3** = nice to have.

## Notes on decisions that need no backend change

- **Deleted credits: "Withdrawn" vs "Voided".** Credits already have a `deletedBy` field, and
  `activityLog` entries record the actor. The UI shows **Withdrawn** when `deletedBy` equals the credit's
  faculty, and **Voided** when it is anyone else (admin/OA). If `deletedBy` is missing on older records,
  the UI falls back to **Withdrawn**. This needs no backend request. (If older records turn out to have no
  `deletedBy` at all, a one-off backfill from `activityLog` would be a P3 data task.)
